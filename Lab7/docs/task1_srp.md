# Завдання 1. SRP: оцінки студента (варіант 3)

Вихідний клас: `grades/legacy/StudentGradeManager` — один метод `processStudentAcademicRecord` робить п'ять різних справ.

## 1. Причини для зміни (reasons to change)

| № | Причина для зміни | Блок у вихідному методі | Приклад зміни |
|---|---|---|---|
| 1 | Правила валідації вхідних даних | 1. Перевірка вхідних оцінок | Допустима шкала оцінок стане 0–200 |
| 2 | Формула середнього бала | 2. Перший цикл (зважування ECTS) | Перейти від зваженого до простого середнього |
| 3 | Правила призначення стипендії | 2. `hasFailedCourses`, пороги 90 / 75, суми 2910 / 2000 | Нові пороги або сума стипендії |
| 4 | Формат академічної довідки | 3. Формування витягу | Додати дату або підпис у довідку |
| 5 | Формат і місце CSV-реєстру | 4. Експорт у CSV | Інший роздільник або папка, окрема база даних |
| 6 | Канал і текст сповіщення куратору | 5. Відправка звіту | Замінити пошту на Telegram |

Окрім цього, у класі змішано порядок виконання кроків (оркестрація): це сьомий, неявний «привід» змінювати клас.

## 2. Декомпозиція

| Клас | Роль | Єдина причина для зміни |
|---|---|---|
| `CourseGrade`, `AcademicRecord`, `ProcessingResult` | Сутності доменної моделі (`record`) | Склад даних |
| `AcademicRecordValidator` | Валідація | Правила коректності даних |
| `GpaCalculator` | Розрахунок | Формула середнього бала |
| `ScholarshipPolicy` | Бізнес-правило | Умови й розмір стипендії |
| `TranscriptFormatter` | Форматування | Вигляд довідки |
| `CsvRegistryWriter` | Збереження | Формат і місце CSV |

Оркестратор отримує всі залежності через конструктор і лише викликає їх по черзі.

## 3. Метрики

Вимірювання виконано скриптом за такими правилами:

- **WMC** — сума цикломатичної складності методів класу (1 + кількість `if`, `for`, `while`, `case`, `catch`, `&&`, `||`, `?:`); конструктори враховано.
- **CBO** — кількість різних типів, від яких залежить клас, окрім `java.lang` (власні класи та типи JDK).
- **LCOM** — за Чидамбером–Кемерером (пари методів без спільних полів мінус пари зі спільними). Для класів без полів значення не визначене (n/a).

| Клас | Методів | WMC | Макс. CC методу | CBO | LCOM |
|---|---|---|---|---|---|
| **До:** `StudentGradeManager` | 1 | **20** | **20** | 8 | n/a |
| **Після:** `AcademicRecordValidator` | 2 | 10 | 8 | 2 | n/a |
| `GpaCalculator` | 1 | 2 | 2 | 2 | n/a |
| `ScholarshipPolicy` | 2 | 7 | 4 | 3 | n/a |
| `TranscriptFormatter` | 1 | 2 | 2 | 3 | n/a |
| `CsvRegistryWriter` | 2 | 4 | 3 | 9 | 0 |
| `CuratorNotifier` | 1 | 3 | 3 | 0 | n/a |
| `StudentRecordService` | 2 | 2 | 1 | 9 | 0 |

**Висновки.**

- **WMC.** Складність найбільшого методу зменшилась з 20 до 8, найбільшого класу з 20 до 10. Сума WMC по всіх класах зросла (20 → 30) через конструктори й допоміжні методи, але тепер вона розподілена.
- **CBO.** Максимальне значення не зменшилось (8 → 9): залежності перерозподілилися. Файлове API зібране в `CsvRegistryWriter`, а всі власні класи координує оркестратор. Решта класів має CBO не більше 3. Покращення в локалізації: зміна файлового API зачепить один клас, а не весь God Object.
- **LCOM.** Метрика малоінформативна: у вихідного класу немає полів. Класи з полями (`CsvRegistryWriter`, `StudentRecordService`) мають LCOM 0, але тривіально: у кожного по одному методу, що використовує їхні поля.
- **Якісно:** причин для зміни на клас стало 6 → 1.

## 4. Збереження поведінки

`GradesDemo` запускає вихідний і новий код на однакових вхідних даних і порівнює:

- текст повідомлення куратору (він містить довідку, GPA і стипендію);
- останній рядок CSV;
- тип і текст винятку для некоректних даних (оцінка 120; порожній список дисциплін).

## 5. Відомі обмеження вихідного коду (поведінку не змінювали)

- Якщо сума кредитів дорівнює нулю, GPA дорівнює `NaN`: у вихідному коді немає перевірки.
- Помилка запису CSV лише виводиться в `System.err` і не зупиняє обробку.
